# Equion Desk 작업 시나리오와 기획안 평가 (2026-11-08)

[`DESK.md`](DESK.md) 2판으로 실제 작업을 처음부터 끝까지 해 보면 어디가 되고 어디가 막히는지를 본다. 평가 기준은 핵심 용도(연립방정식
모형의 추정·예측 시뮬레이션을 AI와 함께)와 **레고 요구**다:

> 변수·방정식·항등식·블록·모형·가정·시나리오가 **레고처럼** — 저마다 혼자서도 기능하고, 끼워 맞추면 연립방정식 모형이 된다.

모형은 가상의 분기 거시모형이다(실제 자료는 쓰지 않는다 — D30).

| 블록(이름) | 내생(식 → 목표변수) | 외생 |
|---|---|---|
| 수요(`demand`) | 소비 `CN`, 투자 `I`, GDP `Y`(항등식) | 정부지출 `G`, 통계적 불일치 `SD` |
| 대외(`external`) | 수출 `X`, 수입 `M` | 세계수요 `WY`, 환율 `E` |
| 물가(`price`) | 소비자물가 `P`, GDP 디플레이터 `PY` | 유가 `POIL` |
| 금융(`finance`) | 시장금리 `R`(정책금리 반응식) | — |

평가 표시: ○ 2판으로 된다 · △ 일부만 · × 안 된다. `G1`… 은 끝의 빈 곳 목록.

## S0. 시작

- **사람**: Desk에서 폴더를 열고 오른쪽 터미널에서 `claude`. 설정의 'Claude Code에 Equion 알려 주기'를 누른다.
- **Claude**: 안내를 읽고 이 프로젝트의 `CLAUDE.md`에 작업 규칙을 정리한다.
- **평가**: ○ — 1판부터 있던 흐름(Lectern D57).

## S1. 자료 불러오기

1. 사람이 원자료 세 개를 `DATA/raw/`에 넣는다 — 분기 국민계정(엑셀, 명목·실질), 월별 물가·금리(CSV), 세계수요(연간).
2. 사람: "분기로 맞추고, 물가·금리는 분기 평균, 세계수요는 분기로 나눠(Denton), 소비·투자는 계절조정해 줘."
3. Claude가 정리 방법을 적는다. 시리즈마다 출처(파일·시트·열)·주기 변환·계절조정·단위·설명, 그리고 파생 시리즈(`RR = R - P.yoy` 같은 실질금리).
4. Desk 자료 화면: 시리즈 목록(주기·구간·결측·끝 시점), 원자료와 변환 결과를 겹친 차트, 단위근 검정(시리즈 혼자서).
5. 사람이 차트를 보다 이상한 분기를 짚어 Claude에게 보낸다(Shift+→) → Claude가 원자료를 확인한다.

- **평가**: △. 차트·목록은 W4에 있다. 그러나 2판에는 **자료를 어떻게 만드는지 적는 선언형 정의가 없다** — 출처·변환·파생이
  스크립트에만 있으면 Desk가 앱 안에서 다시 계산할 수 없고(K1), 시리즈 하나의 내력도 볼 수 없다 → **G1**.
  원자료가 새로 들어올 때의 흐름(무엇이 바뀌었나)도 없다 → **G2**.

## S2. 개별 식 추정 — 소비함수

1. 사람이 식 작업대(W1)를 열고 목표 `CN`에 `CN c Y CN(-1)`, 표본 1995Q1~2019Q4로 추정한다. 1초 안에 결과가 뜬다.
   계수는 그럴듯하지만 LM p=0.00(계열상관)이 주의로 표시되고, 잔차 차트에서 2008~2009년이 크게 튄다.
2. 사람이 결과를 짚어 보낸다: "계열상관을 없애는 후보를 찾아 줘. Y +, 금리 −, 표본은 같게."
3. Claude가 `equion est`로 후보 여섯 개를 추정한다 — 시차 늘리기, 실질금리, 오차수정형(ECM), AR(1) 오차, 2008Q4 더미. 후보는 Desk 후보 목록에 바로 쌓인다(누가 했는지 표시).
4. 사람이 부호·진단 통과만 거르고 세 개를 겹쳐 본다. 표본 밖(2015~2019를 떼어 두고 예측) RMSE를 비교한다.
5. 사람: "c3과 c5를 식 하나로 과거 재현했을 때 어떻게 달라?" — 식 하나만으로 동태 모의(우변의 다른 변수는 실측, 자기 시차는 풀린 값).
6. 사람이 c5를 **채택**한다 → 방정식 파일의 `CN` 줄이 바뀐다(묻고 저장). 투자·수출·수입·물가·금리 식도 같은 식으로 한다.

- **평가**: 대부분 ○ — 2판의 핵심(W1·K2·K3)이 그대로 맞는다. 다만 5번 **식 하나의 동태 모의**는 화면·명령에 없다.
  엔진에는 있다(`eq.forecast(mode="dynamic")`) → **G3**. 채택된 식이 "어느 블록의 부품인지"는 정할 곳이 없다 → **G5**.

## S3. 항등식

1. 사람이 항등식을 적는다: `Y = CN + I + G + X - M + SD`(통계적 불일치 `SD`), `PY*Y = …`(명목).
2. 사람: "이 항등식이 과거 자료에서 맞는지 봐 줘" — 실측으로 우변을 계산해 실제 `Y`와 비교한다. 불일치가 크면 `SD`를 외생으로 둘지 정한다.

- **평가**: ×. 2판에서 항등식은 방정식 파일의 한 줄일 뿐이고, **혼자서 할 수 있는 일(실측으로 성립 검사·불일치 차트)이 없다** → **G4**.

## S4. 블록 조립

1. 사람이 식과 항등식을 블록 넷으로 묶는다 — 수요·대외·물가·금융.
2. 블록마다 혼자서: 구조 검사(목표가 겹치거나 모르는 변수가 있는지), **블록 HS**(다른 블록의 변수는 실측으로 두고 이 블록만 푼다).
   대외 블록 HS가 2009년에 크게 벗어난다 → 원인이 대외 블록 안이라는 것을 바로 안다.
3. 블록끼리 어떤 변수로 이어지는지 본다 — 수요 → 대외(`Y` → `M`), 물가 → 금융(`P` → `R`), 금융 → 수요(`R` → `I`).

- **평가**: ×. 2판은 모형을 "방정식 파일 하나"로 본다(K4 `[model.main] equations = …`). **블록이라는 부품, 블록 혼자 풀기, 블록 사이의 연결 보기가 없다**
  → **G5(가장 크다)**. 엔진은 식 묶음으로 모형을 만들 수 있어(`merge` — 파일·식·객체) 바탕은 있다.

## S5. 모형 조립

1. 사람이 모형 `core`(수요+물가+금융)와 `main`(core+대외)을 만든다. 금리 반응식을 뺀 `main_fixr`(정책 실험용)도 만든다 — **같은 부품을 다른 모형에서 다시 쓴다.**
2. 조립하면 Desk가 보여 준다: 내생 10 · 외생 5, 블록 분해(동시 블록 1개 — `CN·I·Y·M·P·R`, 나머지는 재귀), 외생 변수의 자료 끝 시점.
3. 투자식을 고치면 `I`를 쓰는 모형(`core`·`main`·`main_fixr`)이 모두 새 식을 쓴다.

- **평가**: △. 구조 화면(W2)은 있다. 그러나 **모형 안에 모형, 부품의 재사용, 조립 화면이 없다** → **G5**.

## S6. 과거 재현(HS)

1. 사람이 `main`을 2005Q1~2019Q4 동태로 푼다 → 변수별 적합도 표(RMSPE 정렬), 실측 대 해 작은 그림, 기간별 풀이 상태(모두 정상).
2. `I`의 RMSPE가 가장 나쁘다. 원인을 따라간다: `I` 식 → 입력 `RR`·`Y` → `RR`의 HS 오차가 크다 → 금융 블록.
3. 사람: "금리식 후보 두 개를 모형에 넣어 HS를 비교해 줘. 파일은 바꾸지 말고." → Claude가 후보를 바꿔 끼워 HS를 두 번 돌린다 → Desk 전후 비교(`R`·`I`·`Y` 좋아짐, `P` 조금 나빠짐).
4. 사람이 하나를 채택하고, 비교한 두 HS를 고정(pin)한다.
5. 한 달 뒤 "그때 그 HS를 다시"를 하려면 — 그때 쓴 식의 글자·계수, 자료, 설정이 기록에 있어야 한다.

- **평가**: △. 1~3번은 W2와 `--vs`로 된다. 4~5번의 **재현성**은 빠졌다 — 기록에 결과만 있고 **어떤 부품의 어떤 판으로 조립했는지(조립 명세)**가 없다 → **G6**.

## S7. 전망(기준선)

1. 사람이 가정 세트 `base`를 연다 — 외생 `G`·`WY`·`E`·`POIL`·`SD`의 2025Q1~2027Q4 경로. 일부는 채우기 규칙(성장률 유지·추세), 일부는 직접 적는다.
2. **보정항**: 마지막 네 분기의 잔차를 보고, 식마다 초깃값을 정한다 — 0, 마지막 잔차 유지, 반감기 4분기로 줄이기.
3. 기준선을 푼다 → 결과 표(수준·전기비·전년동기비·연간 집계)와 차트(과거 실측에 이어서).
4. 사람이 판단 조정을 한다(2025년 소비 보정항 −0.3) → 다시 푼다.
5. 사람: "지난달 전망과 무엇이 왜 달라졌는지 정리해 줘" — 이번 회차와 지난 회차를 비교하고, 가정 변화·자료 갱신·식 변경의 몫을 나눈다.

- **평가**: 1·3·4번 ○(W3·K4, 엔진 `forecast`·`exog_fill`). 2번 **보정항 초깃값 규칙**은 없다(엔진은 경로를 받기만 한다) → **G7**.
  5번 **전망 회차 비교**는 없다 → **G8**.

## S8. 시나리오

1. 사람: "유가 20% 상승, 2025Q1부터 영구" → Claude가 `SCENARIOS/oil20.toml`을 쓰고 `equion sim`.
2. Desk 시나리오 비교: 기준선 대비 `P`·`R`·`CN`·`Y` 차이(수준·%·%p), 승수, 기여도 분해.
3. 같은 시나리오를 `main_fixr`(금리 고정)에도 적용해 통화정책 반응의 몫을 본다 — **시나리오가 모형과 따로 있는 부품이라 어느 모형에나 끼운다.**
4. 사람이 차이 표의 몇 행을 짚어 "메모로 써 줘" → Claude가 차트가 든 md를 쓰고 → Lectern으로 읽는다.

- **평가**: 1·2·4번 ○. 3번은 시나리오 파일이 `base = "baseline"`만 가리켜 **모형을 고를 수 없다** → **G5**.

## S9. 다음 분기 — 자료 갱신과 다시 돌리기

1. 새 분기 자료가 나온다. 원자료를 바꾸면 Desk가 바뀐 시리즈와 값(개정 포함)을 보여 준다.
2. 다시 추정할지 정한다. 계수가 많이 바뀐 식을 표시하고 HS·전망을 다시 돌린 뒤 지난 회차와 비교한다.

- **평가**: ×. **G2**(자료 갱신)·**G8**(회차 비교).

## 평가

**맞는 것**: 2판의 중심 — 식 작업대(W1)·모형 작업대(W2)·전망 작업대(W3), 앱 안 계산(K1), 사람과 Claude의 같은 작업 기록(K2),
스크립트 없는 명령(K3) — 은 가장 많이 되풀이하는 S2·S6·S7·S8과 잘 맞는다. AI와 함께하는 고리(짚어 보내기 → Claude가 후보·HS를 돌림 → Desk에 저절로 뜸 → 사람이 채택)는 그대로 둔다.

**맞지 않는 것**: 2판은 모형을 **파일 단위**로 본다(방정식 파일 하나 = 모형). 그래서 레고 요구의 절반이 빠진다 —
항등식·블록이 혼자서 할 일이 없고, 모형 안에 모형을 넣거나 같은 부품을 여러 모형이 쓸 수 없고, 시나리오를 모형과 따로 끼울 수 없다.
자료와 전망 운영(갱신·회차·보정항)도 빈 곳이 있다.

| # | 빈 곳 | 크기 | 3판에서 |
|---|---|---|---|
| G1 | 자료(시리즈)를 만드는 법의 선언형 정의 — 출처·변환·계절조정·파생 | 큼 | 시리즈 부품 `DATA/series.toml`·`DATA/derived.txt` |
| G2 | 원자료 갱신 — 바뀐 시리즈·값·개정 | 중간 | 자료 회차: 원자료 해시로 바뀜 보기, 기록에 자료 판 |
| G3 | 식 하나의 동태 모의 | 작음 | W1 차트 탭과 `equion est --sim`(엔진 `eq.forecast`) |
| G4 | 항등식 혼자서 — 실측으로 성립 검사·불일치 | 중간 | 항등식 부품: `equion ident --check`, 불일치 차트 |
| G5 | **부품과 조립** — 블록·모형 안의 모형·부품 재사용·블록 HS·블록 연결·시나리오의 모형 선택 | **가장 큼** | 부품 모델(K0)과 조립 작업대(W0) |
| G6 | 재현성 — 어떤 부품의 어떤 판으로 조립했는지 | 큼 | 조립 명세(assembly lock)를 모든 기록에 |
| G7 | 보정항 초깃값 규칙 | 중간 | 보정항 세트에 규칙(0·마지막 잔차·평균·감쇠) — 패키지에 |
| G8 | 전망 회차 비교와 요인 나누기 | 중간 | 회차 기록과 비교(가정·자료·식 변경의 몫) |

**판정**: 2판은 **작업 흐름과 AI 협업 면에서는 맞고, 모형의 구조(레고) 면에서는 모자란다.** 빈 곳은 2판의 방향을 바꾸지 않고
"부품과 조립" 층을 바탕에 더하면 메워진다. 이 층은 패키지에 두어 명령줄·Lectern에서도 쓰고, Desk는 그 위에 조립 작업대를 둔다 — [`DESK.md`](DESK.md) 3판.

## 운영 원칙으로 다시 본 3판

사용자가 더한 원칙:

> 모든 일은 사람이 손으로도 하고 Claude Code에게 맡길 수도 있다. 만든 것은 고칠 수 있고 Claude에게 제안을 받을 수도 있다.
> 다만 **모든 결과는 사람의 눈으로 볼 수 있어야** 한다 — 뒤에서 몰래 돌지 않고 **앞에서 드러나게** 작동한다.

같은 시나리오를 두 방식으로 다시 해 본다 — S2(소비함수)를 ① 사람이 손으로 ② Claude에게 통째로 맡겨서, S6(HS 고치기)을 ③ Claude에게 제안만 받아서.

| 해 본 것 | 3판에서 막히거나 숨는 곳 | 번호 |
|---|---|---|
| ② "소비함수를 골라서 채택까지 해 줘" | 3판은 "채택·조립 고치기는 사람만"이라 맡길 수 없다 — 두 길 원칙과 어긋난다 | V1 |
