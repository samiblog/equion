# Equion Desk — 재연성과 활용성 검토 (2026-11-09)

EViews 프로그램의 장점 — 자료 불러오기부터 분석 결과까지 **명시적으로 재연**되고, 그래서 **자료만 갱신하면 새 결과**가 나온다 — 을 기준으로
기획안([`DESK.md`](DESK.md) 4판과 딸린 문서들)을 검토한다.

**판정**: 지금 안은 결과 **하나하나**는 재연된다(조립 명세·`--replay`). 그러나 **원자료에서 보고서까지 한 번에 다시 하는 단위가 없다**. 새 자료가 오면
사람이 '회차 바꾼 뒤 할 일' 화면의 단추를 여럿 누르고, 노트와 보고서를 따로 갱신해야 한다. 판단 지점(다시 추정할지, 새 계수를 채택할지)도 화면 단추에만
있어 미리 적어 둘 곳이 없다. **제안**: 그 순서와 판단 규칙을 적은 **흐름**(`FLOWS/*.toml`)을 더한다. 그러면 **원자료 + 정의 + 흐름 = 모든 결과**가 되고,
사용자는 원자료를 넣고 '흐름 실행'을 한 번 누른다.

## 1. 재연의 공식과 세 수준

> **원자료**(받은 그대로, 해시) + **정의**(시리즈·식·채택표·모형·가정·보정항·시나리오·보기 — 글 파일) + **흐름**(순서와 판단 규칙) → **모든 결과**

| 수준 | 무엇을 | 어떻게 | 지금 안 |
|---|---|---|---|
| 기록 다시 | 결과 하나를 그때 그대로 | 기록의 조립 명세·자료 회차로 `--replay` | 있다 |
| 흐름 그대로 다시 | 한 달 치 결과 전부를 그때 그대로 | 흐름 기록에 든 회차·정의 사본·판으로 `equion flow replay` | 없다(새로) |
| 새 자료로 다시 | 같은 일을 새 자료로 | 원자료를 넣고 `equion flow run` | 없다(새로) — 지금은 단추 여럿 |

손으로 한 일은 클릭의 기록이 아니라 **정의 파일의 내용**으로 남으므로, 흐름이 그것을 그대로 쓴다. 화면에서 식을 고쳐 채택하든 Claude가 고치든, 다음 흐름 실행은
바뀐 정의로 돈다.

## 2. 지금 기획안 점검

| 요구 | 지금 안 | 판정 | 빈 곳 |
|---|---|---|---|
| 원자료에서 보고서까지 한 번에 | 회차 바꾼 뒤 할 일 화면의 단추 여럿 · 노트 실행 · 보고서 갱신이 따로 | × | 한 번에 다시 하는 단위(**흐름**) |
| 결과 하나를 그때 그대로 | 조립 명세 · `--replay` | ○ | — |
| 손으로 한 작업이 재연에 들어가나 | 정의 파일로 남는다 | ○ | 분석 탭의 단발 분석은 노트나 흐름에 넣어야 다시 돈다('흐름에 넣기') |
| 판단 지점(다시 추정·채택) | 화면 단추로만(Q18) | △ | 흐름에 정책으로 미리 적기(채택 기준·멈춤) |
| 새 자료로 기간이 밀릴 때 | 전망 구간·HS 범위를 `2025Q1:2027Q4`처럼 절대 기간으로 | × | 상대 기간(§5) |
| 처음부터 다시 만들 재료 | 원자료가 git 기본 제외(Q9), 묶어 보내기에서 묻는다(Q20) | △ | 원자료가 없으면 해시로 무엇이 없는지 알리기, 보관 규칙 |
| 판이 바뀌면 | 허용오차 비교만(장면 9) | △ | 흐름 기록에 판, 정확한 재연은 그 판의 설치본 |
| 무작위(확률적 모의) | 씨앗 규칙 없음 | △ | 씨앗을 정의에 적는다 |
| 결과물까지(보고서·엑셀) | 보고서 갱신·엑셀 내보내기는 있다 | △ | 흐름의 마지막 단계로 |

## 3. 제안 — 흐름

흐름은 **무엇을 어떤 순서로, 판단 지점에서는 어떤 규칙으로** 할지를 적은 파일이다. 단계는 작업 명령(K3)·분석 명령의 이름이고, 부품은 이름으로 가리킨다(레고).

> **형식**: 아래 TOML 초안 대신 명령 한 줄씩의 Equion 스크립트(`.eqs`)로 쓰기를 권한다 — 내용은 같고 더 짧으며 터미널·노트·AI와 말이 같다([`DESK_SCRIPT.md`](DESK_SCRIPT.md), Q26).

```toml
# FLOWS/monthly.toml (초안) — 새 원자료로 이번 달 전망과 보고서까지
title = "월간 전망"
model = "main"

[[step]]
do = "data.build"            # 원자료 → 새 자료 회차
inbox = "ask"                # DATA/raw/inbox/의 새 파일이 어느 출처를 바꾸는지 한 번 묻는다
use = true                   # 만든 회차로 바꾼다

[[step]]
do = "check"                 # 불러오기 틀 · 조립 · 외생 자료 끝
stop_on = "error"

[[step]]
do = "estimate"
eqs = "adopted"              # 채택한 식 모두 — 같은 글자, 표본은 식의 정의대로
adopt = "if_pass"            # 기준([criteria])을 통과하면 새 계수 채택, 아니면 옛 계수 + 멈춤 표시

[[step]]
do = "hs"
range = "2005Q1:last"

[[step]]
do = "sim"
scenarios = ["base", "oil20", "wy_m2", "krw10"]
range = "next:12"            # 자료 끝 다음 분기부터 12분기

[[step]]
do = "note"
run = ["notes/자료점검.md"]

[[step]]
do = "report"
from = "reports/전망_지난달.md"     # 지난 보고서의 구역을 이번 기록으로 바꿔 새 보고서
to = "reports/전망_{vintage}.md"

[[step]]
do = "export"
views = ["core_hs", "risk"]
xlsx = "exports/전망_{vintage}.xlsx"
```

| 규칙 | 내용 |
|---|---|
| 흐름은 명시다 | 무엇이 어떤 순서로 도는지, 판단 지점에서 무엇을 하는지 파일에 다 적혀 있다. 단계는 등록부의 명령뿐(허용 목록 — K1) |
| 실행은 누를 때만 | '흐름 실행'·`equion flow run`. 원자료가 들어와도 저절로 돌지 않는다(§2.4-1) |
| 판단은 미리 적은 정책으로 | 채택 기준을 통과하지 못한 식, 조립 오류, 틀 검사 실패에서는 **멈추거나 표시**하고 사람이 본다. 정책이 '채택'이면 바뀜 기록에 "흐름 monthly가 채택"으로 남는다 |
| 단계마다 기록 | 단계는 저마다 보통 기록(`data:`·`est:`·`hs:`·`sim:`·`an:`)을 남기고, 흐름 기록(`flow:monthly_0007`)이 그것을 묶는다 — 쓴 정의 파일의 사본·회차·판·단계별 상태·지난 실행과의 차이 |
| 다시 쓰기는 보인다 | 입력이 같은 단계는 다시 계산하지 않고 그 기록을 다시 쓸 수 있다 — 흐름 기록에 "재사용: hs:hs_0031(입력 같음)"으로 적힌다 |
| 손과 Claude 둘 다 | Desk의 흐름 화면에서 단계를 넣고 빼고 순서를 바꾸거나, 글로 고친다. 카드마다 '흐름에 넣기'. Claude에게 "이번 달 흐름 돌려 줘"는 `equion flow run monthly` 한 줄이다 |
| 흐름도 부품 | 흐름이 다른 흐름을 포함한다(`include = "FLOWS/data.toml"`). 노트도 단계가 된다 |

**흐름 화면**(Desk):

```text
 흐름 monthly · 월간 전망                                [미리보기] [실행] [이 단계부터 다시]
 ─────────────────────────────────────────────────────────────────
 ✓ 1 자료 만들기    d2026-12a · 새 기간 2025Q4 · 개정 4분기(CN·I·Y)
 ✓ 2 검사          문제 0
 ! 3 다시 추정      10식 중 9 새 계수 채택 · demand:I 기준 미달(RR t −0.9) → 옛 계수 유지  [보기]
 ✓ 4 HS            hs:hs_0040 · Y RMSPE 0.7% → 0.8%
 ✓ 5 전망·시나리오   sim:2026-12_base 외 3 · 2026년 성장률 1.8% → 1.7%
 ✓ 6 노트          자료점검.md 구역 5 새로
 ✓ 7 보고서         reports/전망_d2026-12a.md · 숫자 바뀐 칸 23
 ✓ 8 내보내기       exports/전망_d2026-12a.xlsx
 기록  flow:monthly_0007 (work/flow/monthly_0007/summary.md)
```

| 명령 | 하는 일 |
|---|---|
| `equion flow list` | 흐름 목록 |
| `equion flow plan <흐름>` | 실행하지 않고 할 일 — 단계, 쓸 입력, 다시 쓸 기록, 멈출 만한 곳 |
| `equion flow run <흐름> [--from 단계] [--set 키=값]` | 실행 → 흐름 기록. `--set`으로 매개변수(예: 시나리오 목록) |
| `equion flow replay <흐름 기록>` | 그때의 회차·정의 사본·판으로 그대로 다시 |
| `equion flow new --from-records <기록…>` | 작업 기록의 명령들로 흐름 초안 — 탐색하며 한 일을 흐름으로 굳힌다 |
| `equion flow export <흐름> --py` | 같은 일을 하는 Python 스크립트(워크파일 API)로 — 읽고 고치거나 Desk 밖에서 돌리기용 |

## 4. 자료만 넣으면 — 사용자의 한 달

1. 새 국민계정 엑셀을 `DATA/raw/inbox/`에 넣는다(끌어 놓기).
2. '흐름 실행: monthly'. 첫 단계가 묻는다 — "국민계정_2026-12.xlsx → 출처 na를 바꿈 · 틀 검사 통과". 확인.
3. 작업 줄에 단계가 차례로 돈다. 3단계에서 `demand:I`가 기준에 못 미쳐 옛 계수를 쓴다는 '!'가 뜨지만 흐름은 정책대로 끝까지 간다.
4. 흐름 기록의 요약을 읽는다 — 회차의 개정, 계수 변화표(채택 9 · 유지 1), HS 적합도 변화, 전망 변화와 그 요인(자료·계수·가정), 보고서에서 숫자가 바뀐 칸.
5. `demand:I`는 W1에서 손보거나(장면 2), Claude에게 "I 식 후보를 찾아 줘"를 맡긴다. 고쳐 채택한 뒤 '이 단계부터 다시'(3단계부터).
6. 보고서의 글을 고치고 Lectern으로 pptx.

사람이 한 일은 **원자료를 넣고, 판단이 필요한 한 곳을 보고, 글을 고친 것**이다. 나머지 숫자는 흐름이 다시 만들었고, 무엇이 어떻게 만들어졌는지는 흐름 기록에 다 있다.

## 5. 기간을 상대로 — 전망 구간·HS 범위·표본 끝

새 자료가 한 분기 늘 때마다 기간을 고치면 "자료만 넣으면"이 깨진다. 기간을 자료 끝에 맞춰 적을 수 있게 한다. 실제로 쓴 기간은 기록마다 풀어서 적는다.

| 표기 | 뜻 | 쓰는 곳 |
|---|---|---|
| `last` | 지금 회차의 자료 끝 | HS 범위 끝, 식의 표본 끝(`@smpl 1995Q2 last`) |
| `next:12` | 자료 끝 다음 기부터 12기 | 전망 구간 |
| `last-39:last` | 끝에서 40기 | 이동 표본 |

- 날짜가 박힌 판단 값(보정항의 판단 값, 사람이 친 가정 경로)은 그대로 둔다. 새 회차에서 그 기간이 과거가 되면 흐름이 "판단 값 2칸이 실측 구간으로 들어감"을 표시한다.
- 외생 가정이 새 전망 구간을 다 덮지 못하면 채우기 규칙(`exog_fill`)으로 채우고 '채움'으로 표시한다 — 규칙이 없으면 검사 단계에서 멈춘다.

## 6. EViews 프로그램과 견주기

| 관점 | EViews 프로그램 | Desk 흐름 + 정의 |
|---|---|---|
| 재연 범위 | 불러오기부터 결과까지 | 원자료부터 보고서·엑셀까지 |
| 무엇을 적나 | 명령의 순서 — 어떻게 | 정의 — 무엇을, 흐름 — 순서와 판단 규칙 |
| 손으로 한 작업 | 명령으로 다시 써야 프로그램에 들어간다 | 정의 파일이 바뀌므로 다음 실행에 그대로 들어간다 |
| 결과 | 보통 같은 이름의 객체를 다시 쓴다 | 매번 새 기록, 옛 결과는 남고 차이가 보인다 |
| 판단 지점 | 프로그램 안의 조건문, 또는 사람이 보고 고쳐 다시 | 흐름의 정책(채택 기준·멈춤)으로 미리 적고, 걸린 곳만 사람이 본다 |
| 그때 그대로 | 그때의 프로그램·워크파일을 따로 보관해야 | 흐름 기록이 회차·정의 사본·판을 가진다 → `flow replay` |
| 실패 | 오류에서 멈춤 | 단계 상태·멈춘 까닭 · '이 단계부터 다시' |
| 코드로 보기 | 프로그램 그 자체 | `equion flow export --py`로 Python 스크립트 |

EViews의 프로그램 파일은 읽지도 실행하지도 않는다(D13). 흐름은 우리 형식이다.

## 7. 재연의 경계

| 경계 | 처리 |
|---|---|
| equion 판 | 흐름 기록·조립 명세에 판을 적는다. 같은 판이면 같은 결과, 다른 판이면 허용오차 비교와 판 차이를 보인다. 정확히 그때 그대로는 그 판의 설치본으로(Q25) |
| 수치 차이(BLAS·CPU) | 설치본의 런타임이 같으면 같다. 다른 환경과는 허용오차로 견준다(CLAUDE.md의 원칙 그대로) |
| 무작위 | 확률적 모의·부트스트랩은 씨앗을 정의에 적는다. 적지 않으면 Desk가 정해 기록에 적는다(알아서 한 것) |
| 받아 오는 자료 | `equion data fetch`는 받은 파일을 원자료로 남기고 해시를 적는다. 재연은 받은 파일에서 출발하지, 다시 받지 않는다 |
| 원자료가 없을 때 | 회차에 원자료 해시가 있으므로 "국민계정_2026-11.xlsx(해시 …)가 없음"으로 무엇이 필요한지 알린다 |
| 사람과 Claude의 글 | 노트·보고서의 글은 다시 만들지 않는다. 숫자 구역만 새 기록으로 바뀐다 |
| Python 단계 | 흐름에 `equion run` 단계를 넣을 수 있지만 앱은 실행하지 않는다 — 그 흐름은 터미널에서 `equion flow run`으로(§6-1) |
